# GPU / APU Compare

GPU更新・導入のためのローカル性能比較ツールです。**JSONを原本とする編集可能なWeb表**を採用しました。方式の比較、調査結果、公式資料は [docs/research.md](docs/research.md) にまとめています。

## 公開ページ

**https://yaeemf.github.io/CompeGPU/** から、PC・スマートフォンなどのブラウザーで利用できます。Pythonやアプリのインストールは不要です。

公開版でも絞り込み、行列の並べ替え、公称値／実測値切替、編集、CSV・JSON出力が使えます。公開版のCtrl＋Sは確認後に**その端末のブラウザー内へ保存**します。編集内容と表示設定は他の端末へ自動同期しません。データを移す場合はJSON出力→別端末でJSON読込を使います。「公開データに戻す」は端末内の編集を解除して、読み込み済みの公開カタログへ戻します。公開カタログ更新時も端末の保存内容を勝手に上書きせず、更新があることを表示します。

公開データを全端末向けに更新するには、ローカル版で `data/gpus.json` へ保存してGitHubの `main` ブランチへpushします。GitHub Actionsが検証・静的ファイル生成・Pages公開を自動実行します。失敗時は前回公開版を維持し、[Actions](https://github.com/YAEemf/CompeGPU/actions/workflows/pages.yml)で結果を確認できます。ブラウザー内の編集内容を公開する場合は、JSON出力した内容を原本へ反映してからpushしてください。

静的公開物は `web/` と現在の `data/gpus.json` のみです。サーバー、バックアップ、調査キャッシュは公開物に含めません。GitHubの認証情報をページへ埋め込む必要はありません。

手元で公開版を確認する場合は `python scripts/build_pages.py` で `_site/` を生成し、`python -m http.server 9000 --directory _site` で配信します。出力先が既にある場合は、新しいディレクトリを `--output` で指定してください。通常の `start.bat` は従来どおりローカルファイルへ保存する版を起動します。

## 起動

Python 3.10以上があれば起動できます。外部パッケージ、ビルド、アカウントは不要です。

Windowsでは **`start.bat` をダブルクリック**すると、サーバーをバックグラウンドで起動し、ブラウザを開きます。終了するときは画面の変更を保存してから **`stop.bat` をダブルクリック**してください。ブラウザを閉じるだけではサーバーは終了しません。

起動済みの場合は重複起動せず、既存の画面を開きます。終了用バッチは起動用バッチが記録したプロセスだけを停止します。手動で `python server.py` を起動した場合は、そのターミナルで `Ctrl+C` で終了してください。実行ログと起動情報は `.runtime/` に保存されます。

コマンドからは ` .\start.bat -Port 9000` でポートを変更、`.\start.bat -NoBrowser` でブラウザを開かずに起動できます。エラー時はバッチ画面にメッセージが表示され、キーを押すまで残ります。

ターミナルで直接実行する場合：

```powershell
cd C:\Users\emone\Random\CompeGPU
python server.py
```

ブラウザで **http://127.0.0.1:8765** を開きます。停止はターミナルで `Ctrl+C`。ポートを変える場合は `python server.py --port 9000` とし、表示された127.0.0.1のURLを使います。`index.html` の直接ダブルクリックでは起動しません。

## できること

- GPU名、アーキテクチャ、カテゴリ、Compute Capabilityの完全一致で絞り込み。
- 上部の「公称値 / 実測値」で比較対象を一括切替。表示項目・順序・数値範囲は表示種別ごとに分離。
- 全数値項目に以上・以下・上下限の範囲フィルタ。CC、VRAM、帯域、電力、価格、精度別性能、実測、計算指標、追加の数値項目を複数同時に指定。
- GPUを横、比較項目を縦に表示。ボタンで行・列を入れ替え可能。GPUと比較項目の両方をドラッグで自由に並べ替え、表示方向と順序をブラウザに保存。
- FP64/FP32/FP16、TF32/BF16/FP16/FP8/FP4/INT8/INT4 TensorのDense/Sparseを別項目として管理。
- 基準GPUとの倍率。レイテンシなど小さいほど良い指標は `基準値 ÷ 候補値` で計算。
- 表の項目名クリックで比較指標を選択、GPU名クリックで基準GPUを設定。同じGPUを再クリックすると基準を解除。Ctrl＋クリックでGPU参照ページ（未設定なら選択指標の出典）を開き、ダブルクリックでGPUを編集。
- 価格を入力するとFP32/1万円、公称電力を使うFP32/Wでも比較。
- GPUごとに価格（円）と購入リンク1件を登録。価格をダブルクリックでリンク編集、Ctrl＋クリックで購入ページを別タブで表示。
- 画面からGPUの追加・編集・削除、実測ベンチマーク定義・結果の追加。
- JSON入出力、現在の絞り込み・表示列・列順・行順を反映するCSV出力（UTF-8 BOM、Excel対応、出典等の補助情報付き）。CSVは分析用で、再取込はJSONを使用。
- 保存時の検証、変更前のバックアップ、複数画面間の上書き競合検出。

編集したら「一覧に反映」→「保存（Ctrl＋S）」、または **Ctrl＋S** で保存します。GPU編集・購入リンク編集・実測定義のフォームを開いたままCtrl＋Sを押した場合も、入力内容を検証して一覧へ反映した後、保存に進みます。保存ボタンとCtrl＋Sのどちらも、ファイルへの上書き前に確認ダイアログを表示します。キャンセルすると編集内容は一覧に残り、ファイルは変更しません。GPUデータに変更がない場合も、表示設定と最後の手動順を保存する確認ダイアログを表示します。この場合はGPUデータのJSONを上書きせず、ブラウザー内の表示設定を保存します。表示設定は従来どおり自動保存もされます。

一覧への反映はメモリ上の変更です。保存先は `data/gpus.json`、バックアップは `data/backups/`。未保存で画面を離れるとブラウザが確認を表示します。

ファイルを直接編集する場合は `data/gpus.json` を編集後、画面を再読込してください。画面での変更が未保存なら先にJSON出力で退避します。競合時もJSON出力→再読込→差分を反映する手順で回復できます。バックアップから復元する場合はサーバーを停止して対象JSONを `data/gpus.json` にコピーします。バックアップは自動削除しません。

## 範囲フィルタと表示項目

配色はダークモードです。画面左上の「絞り込み」ボタンは、サイドバーの開閉にかかわらず常に表示されます。このボタンで開閉でき、閉じると表が空いた横幅を使います。閉じても絞り込み条件は有効で、開閉状態は同じブラウザ・同じURLで再読込後も保持します。リセットボタンはサイドバー下部にあり、条件入力部分とは別に固定表示します。

GPU名は画面上で「NVIDIA」「GeForce」を省略して表示します（例：`GeForce RTX 4090` → `RTX 4090`、`NVIDIA A100 80GB PCIe` → `A100 80GB PCIe`）。正式名称はGPU名にマウスを合わせると確認でき、編集欄・データベース・JSON・CSVには正式名称を保持します。検索は正式名・省略名のどちらにも対応します。

GPU名の下には構成の説明文を表示しません。「世代（アーキテクチャ）」「接続形式」「冷却方式」「ボード仕様」「占有スロット数」を独立した比較項目に分け、公称値の初期表示に追加しています。既存の表示設定にも初回だけ追加し、その後は表示・非表示や順序を自由に変更できます。GPU編集フォームで各項目を編集でき、元の構成文字列は「構成（元の表記）」として保持します。元の記録にない情報は推定で補わず `—` と表示します。

上部左端の選択欄で「公称値」「実測値」を切り替えます。公称値には公開仕様と公式仕様から算出した理論値（`published` / `derived`）を、実測値には測定値・測定結果の集計値（`measured` / `aggregate`）だけを表示します。実測表示には公称のCC・VRAM・帯域・TDP・価格を混在させません。GPU名やアーキテクチャ等は比較対象を識別する情報として共通です。実測の消費電力や帯域を比較したい場合は、測定条件を持つ実測定義として登録してください。

比較指標、表示項目、範囲フィルタの候補も表示種別ごとに切り替わります。表示項目とその順序は公称値・実測値それぞれで保存し、切替時に範囲条件も相互に持ち越しません。CSVも選択中の表示種別に限定します。実測定義を追加すると自動的に実測表示に切り替わります。実測データがなければ未登録と表示し、公称値で補完しません。

数値セルは値だけを表示し、「算出値」「実測値」「注記あり」等の補足は付けません。単位は項目名にまとめ、倍率もセル内に記号を付けず数値のみを表示します。出典・値の種別・計算式・個別注記はGPU編集画面で確認できます。メモや出典などを項目として明示的に選択した場合は、その項目の内容を表示します。表幅は内容に合わせて決まり、少ない項目を画面全幅に引き伸ばしません。

「数値フィルタを追加」で項目を選び、「＋範囲を追加」を押します。「以上」だけ、「以下」だけ、両方のいずれも指定できます。境界値を含み、0も有効です。空欄は制限なし。値が未収集のGPUは、上下限のどちらかが指定されたフィルタでは除外されます。表示していない項目にも範囲を設定でき、すべての条件を同時に満たすGPUを表示します。下限が上限より大きい等の入力はエラー表示になり、修正するまで一致するGPUは表示しません。

CCは小数ではなく世代の組として比較します。`8.10` は `8.9` より上です。CC欄には `8.9` の形式で入力してください。CUDA非対応のAMD APUはCCを空欄で登録し、表では `x` と表示します。リセットで範囲条件も解除できます。

「表示項目を編集」のチェックで表示・非表示を切り替えます。公称値の初期表示は **CC、VRAM、帯域、CUDA FP64、CUDA FP32、CUDA FP16、Tensor FP32、Tensor TF32、Tensor FP16、Tensor BF16、価格** の順です。実測値の初期表示は登録済みの実測指標です。TensorはDenseを初期選択し、Sparseも個別に追加できます。GPU名と編集操作は各GPUの見出しに表示します。Tensor FP32はIEEE FP32入力の意味であり、FP32蓄積やTF32とは別です。Tensor FP16/FP8はFP32蓄積を初期項目とし、FP16蓄積・蓄積精度未公表の項目を別に選択できます。

初期状態は **横にGPU、縦に比較項目** の転置表示です。「GPUを行に表示」で横に比較項目・縦にGPUの表示に切り替えられます。GPUと比較項目それぞれの見出しの「⠿」をマウスでつかみ、同じ種類の移動先の見出しへドロップすると、行・列の両方を自由に並べ替えられます。GPUハンドルはフォーカスして矢印キーでも移動できます。比較項目は設定画面の表示順一覧でもドラッグでき、↑↓ボタンでも移動できます。「初期表示に戻す」は比較項目の選択と順序を復元します。

GPU・比較項目の最後の手動順序は、同じブラウザー・同じURLに自動保存します。指標や昇降順によるソートは一時的な表示で、保存済みの手動順を上書きしません。再読込すると最後の手動順で復元します。以前の版でソート中に保存した場合も、記録された手動順を優先します。「手動の順序」を選ぶだけでソート結果を手動順として保存することはありません。まだ手動順を作っていない場合に「手動の順序」を選ぶと、データベースの登録順で表示します。Ctrl＋Sでも並び順と表示設定をブラウザーに保存し、GPUデータの編集があれば従来どおり確認後にJSONへ保存します。

比較指標は表の項目名をクリックして選択します。選択した項目名を強調し、その値によるGPUの並べ替え、既知値のみの絞り込み、基準比を連動させます。同じ項目名を再クリックすると昇順・降順を切り替えます。表示していない項目を比較したいときは「表示項目を編集」で追加してください。基準比とGPU名の見出しのクリックは、それぞれ倍率・名前によるソートのみを行います。

表のGPU名をクリックすると基準GPUに設定し、数値指標を選択中なら基準比の項目を追加します。同じGPU名をもう一度クリックすると解除します。選択中のGPU名とそのGPUの行または列を強調します。行列を入れ替えた表示でも同じ操作です。CCや文字列項目は倍率に意味がないため基準比を表示しません。比較指標は公称値・実測値それぞれで記憶し、基準GPU・ソート設定とともに再読込後も復元します。

GPUをドラッグ・矢印キーで動かすと「GPUの表示順」が「手動の順序」になります。「指標で並べ替え」に戻すか、項目名・昇降順を選ぶと数値ソートに戻ります。絞り込み中にGPUを移動しても、隠れているGPUの相対的な順序は保持します。表示方向、比較項目の選択・順序、GPUの手動順序は同じブラウザ・同じURLに保存され、GPUデータの変更とは独立しています。CSVにも表示方向と両軸の順序を反映します。

精度別の全理論指標、実測定義、メモ、出典URL・確認日、値の種別・算出根拠など、GPUデータ内の項目を列候補として自動検出します。任意の追加フィールドや入れ子の値も対象です。項目名は `sources / 0 / url` のようなパスで表示し、オブジェクト・配列全体もJSONとして表示できます。新しい指標定義を追加すると、値の登録がなくても列と範囲フィルタの候補に現れます。

公称・算出演算性能364レコードを登録しています（Ryzen追加までの295件、共通行列項目への対応56件、Gaudi2・MI250の13件）。共通項目は既存値の別項目への対応を含みます。対象構成・出典・計算式・資料間の差異は [カタログ調査記録](docs/catalog-research-2026-11-11.md) を参照してください。**T10/T40は実機公開画像・販売元仕様とNVIDIAの命令レートから参考理論性能を追加しました。メーカー保証の公称値ではありません。** [T10/T40再調査](docs/t10-t40-research-2026-11-11.md)に根拠と限界を記録しています。FP16/FP32蓄積のSKU別TensorピークとT40の電力は未確定、CC 7.5はTU102/Turing識別からの推定です。

Thorは公式Technical BriefでFP16 Dense 258 TFLOPS、INT8 Dense 517 TOPSの直接公表を確認しました。**蓄積精度別のTensor値とBF16/TF32の一部は、命令の対応・NVIDIA公開参考モデルに基づく仮定付きの推定です。** 出典の公表値・推定値・その前提を [Thor再調査](docs/thor-research-2026-11-11.md) に分けて記録しています。追加調査でCUDA FP64は公式CC 11.0のFP32:FP64比64:1から0.126 TFLOPSを登録し、Tensor FP64・INT4は公式の入力型対応表に基づいて非対応 `x` に更新しました。非Tensor CUDA FP16はNVIDIA公式資料では未確認ですが、参照リンクのTechPowerUp掲載値8.064 TFLOPS（FP32と1:1）を第三者データベース値として登録しました。

表の `—` は未調査・未確認・条件不明、`x` は非対応（未搭載）の計算機能です。`metric_status` または基本項目の `field_status` が `not_supported` の場合だけ `x` を表示します。どちらも数値として扱わず、数値範囲フィルタでは除外します。実測値の未登録は `—` のままです。CSVも非対応は `x`、未確認は空欄として出力します。`metric_status` に非対応・未公表・未確認等の理由、`field_provenance` に基本仕様の確認状態を記録し、未知の値を0で補いません。出典の明記された公開値と、公式の演算レート比から求めた算出値を区別しています。

**Ryzen AI Max+ 395には公開CPU実測2件とLLM実測の集計8件を収録しました。** 「実測値」でGeekbench 6.4.0のCPU single/multi、llama.cppのVulkan/ROCm、モデル・prefill/generation別の結果を比較できます。「公称値」にはCPU構成、GPUの共通演算項目、NPU TOPS等を追加しています。CPU・GPU・NPUの数値は足し合わせず、測定条件を分けて管理します。構成・出典・GPUのsingle/dual issue条件・共有メモリの扱いは [Ryzen AI Max+ 395調査記録](docs/ryzen-ai-max-395-research-2026-11-12.md) を参照してください。従来のNVIDIA構成には実測値を補完していません。

**Gaudi2にはGEMM 15件と高バッチLLM 4件、MI250にはHPL/HPCG 2件を追加し、全体の実測・集計値は31件です。** 公称値の共通Matrix項目と実測の新項目は、既存の手動順を保ち初回だけ末尾へ追加します。Gaudi2のFP16/TF32/FP32対応とピーク未確認を区別し、MI250はMI250Xや単一GCDの値と混同しません。128GBは2 GCD×64GB、電力は500W公称/560Wピークです。Gaudi2のLLM合計tokens/sは単一ユーザーの生成速度とは異なります。出典・測定条件・公式ページ内の版表記の矛盾は [Gaudi2 / MI250調査記録](docs/gaudi2-mi250-research-2026-11-12.md) を参照してください。

RTX 4090/5090のFP32はNVIDIA RTX Blackwell白書の公表値82.6/104.8へ更新しました。Tensorの蓄積精度、Dense/Sparseを分け、丸めのある公称値は資料の記載を維持しています。Thorの128GBは共有メモリ、130WはCPUやメモリを含むモジュール電力です。

「広告AI TOPS」は精度条件が異なる可能性があるため独立項目です。基準倍率を表示しません。CUDAとTensor、DenseとSparse、異なる入力精度や蓄積精度を混ぜないでください。TFLOPSは毎秒10¹²浮動小数点演算、整数のTOPSも毎秒10¹²演算です。FMAは2演算として扱います。

Gaudi2・MI250の全51公称項目を再点検し、MI250非行列FP16の参考理論値90.5216 TFLOPS、Gaudi2 FP16実測4件、非対応・対象外・未公表の根拠を補完しました。欠測セルにマウスを合わせると理由が分かります。Gaudi2のFP16/TF32/FP32公称ピークは未公表のため—を維持しています。[欠測再調査と全件監査](docs/accelerator-completion-2026-11-12.md)を参照してください。

## GPUの追加・項目別の出典

通常は「＋GPUを追加」で基本情報、出典URL、確認日、必要な数値を入力します。SKUを区別できる一意のIDを使います。数値の空欄は欠損値です。

各GPUの「詳細JSON」では項目ごとに出典・種別・算出根拠を設定できます。「フォームをJSONに反映」→JSONを編集→「JSONを適用」→「一覧に反映」→ファイル保存の順です。出典は `sources` に登録し、値からそのIDを参照します。

```json
{
  "value": 8.064,
  "source": "spec",
  "kind": "derived",
  "note": "Jetson T5000: 2560 × MAXN 1.575 GHz × 2 / 1000。クロック条件の出典もsourcesに登録する"
}
```

値の種別は `published`（公開仕様）、`derived`（算出）、`measured`（測定）、`aggregate`（集計）。フォームで理論値の数値を変更すると `published` / 主な仕様出典に置き換えます。変更していない値のメタデータは保持します。別の種別・出典を使うときは詳細JSONで設定してください。

## 価格と購入リンク

各GPUの「編集」で「価格（円）」と「購入リンク（価格のリンク先・1件）」を入力し、一覧に反映してからファイルに保存します。データ上は `price_jpy` と `purchase_url` の組として保存します。リンクは任意の `https://` または `http://` のURLを1件登録でき、空欄にすれば解除できます。

公称値表示の「価格（円）」を **ダブルクリック**すると、そのGPUの購入リンクだけを編集できます。リンクのない価格や未入力の `—` からも編集でき、空欄で解除できます。「リンクを更新」の後は、上部の「保存（Ctrl＋S）」で永続化してください。価格の数値は変更しません。

購入ページを開く操作は **Ctrlを押したまま価格をクリック**です。通常のクリックやダブルクリックでは移動しません。キーボードでは価格セルにフォーカスしてEnterでリンク編集、Ctrl＋Enterで購入ページを開けます。価格の項目名のクリックによる比較・ソート、上下限フィルタ、ドラッグによる並べ替えも利用できます。JSONとCSVには価格・購入リンクを保存します。実測表示には混在させません。

既存の表示設定にもこの機能の初回適用時に価格を追加します。その後は他の項目と同じく「表示項目を編集」で非表示にできます。初期データの価格と購入リンクは未登録です。税・新品/中古・購入時点・単体/システム一式など、価格の条件はGPUメモに記録してください。

新しい理論指標もJSONの `metrics` に `{ "id": "unique-id", "name": "表示名", "unit": "単位", "direction": "higher", "note": "条件" }` を追加すれば表示項目の候補・編集欄に反映されます。`memory_gb` 等の予約IDは使えません。GPU側の `performance` へ同じ指標IDで値を登録します。

## 実測ベンチマークを追加

1. 上部の「実測定義を追加」から定義を追加します。
2. バージョン、モデル/行列サイズ、入力・蓄積精度、Dense/Sparse、バッチ、GPU数、CUDA・ライブラリ・ドライバ、電力制限、ウォームアップ・反復数・集計方法を条件に記録します。条件が違えば別IDにします。
3. GPU編集画面の該当定義に、測定値・測定レポートのURL・取得日を入力します。ローカルの測定記録はリポジトリ等の参照可能なURLを出典にできます。
4. 表の該当する項目名とGPU名をクリックして比較指標・基準GPUを選び、ソートとフィルタを設定します。

条件の同一性は登録者が確認します。定義に書いた条件どおりに測定されたかの自動判定やベンチマーク実行は行いません。複数GPUのシステム全体の値を単純にGPU数で割らないでください。MLPerfなら版・モデル・シナリオ・division・accuracy・GPU数を、Blenderなら版・シーン・CUDA/OptiX・集計方法をそろえます。

`benchmarks` が定義、各GPUの `results` が値です。実測と仕様の数値は別の領域に保存します。定義の修正や削除はJSON編集で行えます。

```powershell
python server.py --check

```

Node.jsは比較ロジックのテスト時のみ必要です。画面の操作確認は、PlaywrightとChromiumがある開発環境で `python tests/browser_check.py` を実行できます。インストール済みChromeを使う場合は `python tests/browser_check.py --channel chrome`。テストは一時データを使い正本を変更しません。

ローカルの1人〜少人数の調査用です。127.0.0.1でのみ待ち受け、外部CDNやクラウド保存を使用しません。複数人の同時編集、履歴の検索、大量の測定結果の管理が必要になったらSQLite等への移行を検討してください。

GPU名のCtrl＋クリックは「GPU名から開く出典URL」を優先します。15機種をTechPowerUpに統一し、T40は既存の出典を維持しています。[参照リンクの対応表と確認範囲](docs/reference-links-2026-11-11.md)を参照してください。各性能値の公式出典・算出根拠は保持しています。
